# Watchfloor M1 — Ingest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real items from real feeds land in SQLite on a schedule, and one dead feed never takes down the run.

**Architecture:** Four adapters (`rss`, `json`, `news_sitemap`, `google_news`) share one polite HTTP layer that honours ETag/Last-Modified, rate-limits per host, and refuses anything `robots.txt` disallows. Every adapter emits the same raw shape; one normalizer turns that into a `NewItem` with a canonical URL and canonical timestamps. A scheduler polls each source on its own interval with persisted per-source fetch state and exponential backoff.

**Tech Stack:** TypeScript, Node 26, `node:sqlite`, `undici` (Node built-in `fetch`), `fast-xml-parser`, vitest.

## Global Constraints

Every task's requirements implicitly include this section.

- **Node 26.** No native modules.
- **Never delete anything.** No `rm`, no history rewrites, no `fs.rm`/`fs.unlink`/`fs.rmdir`. Obsolete files go to `attic/` via `git mv`. **Never edit an applied migration** (`0001_init.sql`, `0002_constraints.sql`) — the runner has no content hashing, so an in-place edit silently diverges the database from the tree. New schema is a new migration.
- **Zero absolute paths anywhere in the tree.** All paths via env or `import.meta.dirname`.
- **`src/db/connection.ts` is the ONLY file permitted to import `node:sqlite`.**
- **Politeness is non-negotiable.** RSS/API only, never scraping. Respect `robots.txt`. Send a real User-Agent identifying the project. Rate-limit per host. Cache aggressively via conditional requests. If a source has no feed and no API, it goes in `docs/sources-wishlist.md` — never a scraper.
- **Store links and short excerpts, never full article text.** Excerpts capped at **300 characters**.
- **Timestamps are canonical or rejected.** Every `published_at` and `fetched_at` must be `YYYY-MM-DDTHH:mm:ss.sssZ`. `insertItem` throws `InvalidTimestampError` otherwise — adapters normalize, they do not pass through.
- **Zero-dollar rule.** No source may require payment or a card on file. Every new external service gets a `docs/costs.md` entry before it ships.
- **Items are append-only.** Never UPDATE or DELETE `items`, `item_scores`, or `item_clusters`.
- **No new runtime dependency without justification** recorded in the task report.
- **Commit after every passing test run.** Never rewrite history, never `git push`. Branchless on `main`.

### Why canonicalization moved into M1

`item_key` is `sha256(canonical_url)` and `items` is append-only. If M1 writes `item_key` from a raw URL and M2 then introduces canonicalization, every already-ingested article gets a *different* `item_key` on its next fetch — the history fragments into two unrelated chains and no correction is possible, because append-only storage forbids rewriting the old rows. Canonicalization must therefore be correct **before** the first real item lands. M2 keeps clustering and scoring; it loses only the URL step.

### Two normalizer obligations the schema forces

- **`items.item_type` is NOT NULL with a CHECK** (`event | analysis | press`). Full classification is a §5.1 concern that belongs to M2/M4b, but M1 cannot insert a row without a value. M1 assigns it from a **single mechanical rule** (below) and M2 refines.
- **`items.canonical_url` is NOT NULL** and feeds `item_key`. Covered by moving canonicalization here.

### Task 1: Fetch-state schema

**Files:** Create `db/migrations/0003_fetch_state.sql`, `src/db/fetchState.ts`; Test `tests/db/fetchState.test.ts`

**Interfaces produced:**
- `interface FetchState { sourceId, etag, lastModified, lastSuccessAt, lastFailureAt, lastError, consecutiveFailures, nextEligibleAt }`
- `getFetchState(db, sourceId): FetchState | null`
- `recordSuccess(db, sourceId, { etag, lastModified, itemCount }): void`
- `recordFailure(db, sourceId, error: string): void` — applies exponential backoff
- `isEligible(db, sourceId, now: string): boolean`

This table is **mutable** — it is operational state, not history, and is explicitly not append-only. Do not add append-only triggers to it.

Backoff must satisfy one invariant, which matters more than any particular formula:

> **A source in backoff must never become eligible sooner than its own healthy poll interval, at any failure count.**

Delay grows per consecutive failure and is bounded by a ceiling; `consecutiveFailures` resets to 0 on success; a source in backoff is skipped, not retried in-loop.

An earlier draft of this plan specified `min(poll_interval * 2^consecutiveFailures, 6h)`. **That formula is wrong** and is retained here only as a warning: for any source polling less often than every 6 hours, the ceiling lands *below* its normal cadence, so backoff would make a failing source eligible more often than a healthy one. Any ceiling must therefore be at least the source's own poll interval. Test the invariant as a property across a spread of intervals rather than asserting a formula — a relative "doubles each failure" assertion passes for any base and catches nothing.

Schema must also record a rolling `items_yielded_7d` count, because §7's source-health page needs "items yielded over the last 7 days" and computing it from `items` alone is a full scan.

- [ ] Run it, confirm it fails
- [ ] Write `0003_fetch_state.sql` and `fetchState.ts`
- [ ] Run tests, confirm green
- [ ] Commit

### Task 2: URL canonicalization

**Files:** Create `src/normalize/url.ts`; Test `tests/normalize/url.test.ts`

**Interfaces produced:** `canonicalizeUrl(raw: string): string`

Must: lowercase scheme and host, strip `www.`, drop the fragment, remove tracking params (`utm_*`, `fbclid`, `gclid`, `mc_cid`, `mc_eid`, `ref`, `source`, `at_*`), sort remaining query params for stability, strip a trailing slash on non-root paths, and force `https` for known-HTTPS hosts. It must be **idempotent** — `canonicalize(canonicalize(x)) === canonicalize(x)` — and that property gets a test.

Do **not** perform network redirect resolution here; that is the Google News adapter's job and belongs on the fetch path, not in a pure function.

Golden-file test: a checked-in table of ~30 input→output pairs, so a future change to the rules shows up as a reviewable diff. This is the same discipline §6 asks for on scoring.

- [ ] Write the failing golden-file test plus the idempotence property test
- [ ] Run it, confirm it fails
- [ ] Implement
- [ ] Run tests, confirm green
- [ ] Commit

### Task 3: Polite HTTP layer

**Files:** Create `src/fetch/http.ts`; Test `tests/fetch/http.test.ts`

**Interfaces produced:**
- `interface FetchResult { status, body: string | null, etag, lastModified, notModified: boolean }`
- `politeFetch(url, opts: { etag?, lastModified?, timeoutMs?, maxBytes? }): Promise<FetchResult>`

Requirements: send `If-None-Match` / `If-Modified-Since` when state exists and return `notModified` on 304 without a body; send `User-Agent: watchfloor/<version> (self-hosted personal feed reader; single user)`, with the version read from `package.json` and **no URL or email** — an earlier draft asked for a `+<repo url>` segment, but no repository URL exists or ever will (the spec forbids pushing), and an email would ship the owner's personal address to every feed operator we poll; enforce a per-host minimum interval (default 2s) across concurrent calls; enforce a byte ceiling so a 13 MB feed cannot exhaust memory; classify 429 and 5xx as retryable and 4xx as permanent.

Tests use a local `node:http` server on an ephemeral port — **no network in tests**, per §6.

### Task 4: Normalizer

**Files:** Create `src/normalize/item.ts`; Test `tests/normalize/item.test.ts`

**Interfaces produced:**
- `interface RawItem { url, title, publishedAt?: string | null, summary?: string | null, author?: string | null, raw: unknown }`
- `normalizeItem(raw: RawItem, source: Source, fetchedAt: string): NewItem`

Responsibilities: canonicalize the URL via Task 2; convert `publishedAt` from whatever the feed emitted (RFC-822, ISO with offset, epoch seconds) into canonical UTC, or `null` if unparseable — **never** guess a date; truncate `summary` to 300 characters at a word boundary; copy `beats` from the source config; and assign `item_type` by this single mechanical rule, which M2 will refine:

- source has `tier: event` → `event`
- source is a government primary (`federal-register`, `whitehouse-actions`, `scotus-slip`, `nws-fl-alerts`, `cisa-*`, `nvd-cve`) → `event`
- summary word count ≥ 400 → `analysis`
- otherwise → `press`

Record in the report that this rule is deliberately crude and owned by M2.

### Task 5: robots.txt gate

**Files:** Create `src/fetch/robots.ts`; Test `tests/fetch/robots.test.ts`

**Interfaces produced:** `isAllowed(robotsTxt: string, userAgent: string, path: string): boolean`, `fetchRobots(origin: string): Promise<string>` with a 24h cache.

Must correctly handle the allowlist shape Reuters uses — a long list of named agents followed by `User-agent: *` / `Disallow: /` — and the AP shape, where `User-Agent: *` opens with an empty `Disallow:` meaning allow-all followed by specific denials. Longest-match-wins on path prefixes. Unknown agent falls back to the `*` group.

**This module is a safety gate, not a convenience.** A source whose `robots.txt` disallows our path must be skipped and marked in fetch state, never fetched anyway.

### Tasks 6–9: The adapter farm

All four implement one interface from `src/adapters/types.ts`:

```ts
export interface Adapter {
  readonly type: SourceType;
  fetch(source: Source, state: FetchState | null): Promise<AdapterResult>;
}
export interface AdapterResult {
  items: RawItem[];
  etag: string | null;
  lastModified: string | null;
  notModified: boolean;
}
```

Each task: capture a real response as a checked-in fixture **first**, then write the parser against it. **No network in tests.** Each adapter must survive a malformed entry by skipping that entry and continuing, never by throwing.

- **Task 6 — `rss.ts`:** RSS 2.0 and Atom via `fast-xml-parser`. Fixtures from `krebs`, `simonwillison` (Atom), `npr-news`, `arxiv-cs-ai`.
- **Task 7 — `json.ts`:** per-source shape mappers for `cisa-kev`, `nvd-cve`, `hn-algolia`, `federal-register`, `nws-fl-alerts`. A registry keyed by source id, so adding a JSON source is a mapper function, not a new adapter.
- **Task 8 — `newsSitemap.ts`:** Google-News-schema sitemaps. Reads `<news:title>`, `<news:publication_date>`, `<loc>`. Fixture from AP. Must cap items per run.
- **Task 9 — `googleNews.ts`:** Google News RSS. Strips the ` - Publisher` suffix from titles, and **resolves the `news.google.com` redirect to a publisher URL before canonicalization** — an unresolved redirect would make `item_key` a Google URL hash and break dedupe against the same story from another source. Resolution is a HEAD request through `politeFetch`; on failure, keep the Google URL and mark `geo_confidence`-style low trust rather than dropping the item.

### Task 10: Scheduler
