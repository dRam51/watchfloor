# Watchfloor M7 — Infrastructure map and globe

**Goal (§ brief, M7):** *"clicking a fab site shows me the items about it, the jurisdiction layer
tells me something I didn't already know from reading the lanes, and the globe with live arcs is
something I'd leave running on a spare monitor."*

**Scope (§7.2, §7.4):** MapLibre base, lazy-loaded and code-split. Curated `locations` seed with
`source_url` and `verified_at`. Gazetteer geo-extraction into `item_locations` with confidence.
Fabrication, compute, and jurisdiction layers. Full globe projection: smooth 2D↔globe transition,
atmosphere, day/night terminator, animated supply-chain arcs with pulse-on-news. Ambient mode.
Phone-width degradation to static map + list.

---

## What M0 already built, and what has never run

`locations`, `item_locations`, and `items.lat/lon/geo_confidence` have existed since
`0001_init.sql`. `src/domain/location.ts` implements `upsertLocation`, `listLocations`,
`linkItemLocation`, `getItemLocations`, with a passing test file.

**All of it is unreachable. `locations` holds 0 rows; `item_locations` holds 0 rows; no item has
a `lat`.** That is occurrence **nine** of CLAUDE.md's characteristic defect — with the difference
that this one was scaffolded deliberately for a milestone that had not arrived, rather than wired
to nothing by accident. M7 is the milestone that owns the wiring, and per CLAUDE.md's practice 2,
**the wiring has a named owner here** (Task 5) rather than being assumed to fall out of the
component tasks.

## Three decisions taken before Task 1, because they change the shape of everything after

### DECISION 1 — no tile server, no API key, no third-party host. Vendored Natural Earth.

> §7.2: *"MapLibre GL JS with a free vector tile source as the base."*

**Departing from the literal text, and the departure is an upgrade rather than a shortcut.**
Every "free" vector tile source is one of: an account plus an API key embedded in the client
bundle (MapTiler, Stadia), or a single-maintainer donation-funded host with no uptime commitment
(OpenFreeMap). Both put a **third-party network dependency in the render path of a
loopback-bound, Tailscale-only, single-user dashboard**, and both broadcast which part of the
world the owner is looking at to a host that has no business knowing. A free tier with an account
attached is one pricing-page edit from violating the zero-dollar rule, and CLAUDE.md's standard is
that the system must be *incapable* of spending, not merely configured not to.

What this map actually needs is **country polygons** — the fabrication and compute layers are
~200 hand-curated points, and the jurisdiction layer *is* a country choropleth. Street-level
detail is not in scope at any zoom this view uses.

So: **Natural Earth 1:110m admin-0 countries, public domain (CC0), vendored into
`web/public/geo/` at ~250 KB after coordinate-precision reduction**, behind the same lazy route as
the WebGL bundle. No key, no account, no host, works with the internet unplugged. If street-level
context is ever wanted, a Protomaps `.pmtiles` extract served by our own Fastify is the upgrade
path, and it is still zero-dollar.

### DECISION 2 — no deck.gl, and no second globe library. Verified, not assumed.

> §7.2: *"Add deck.gl layers on top only if a specific layer needs it — evaluate whether
> MapLibre's native layers cover the requirement first and tell me before pulling deck.gl in."*
> *"evaluate whether its transition is good enough before considering a separate globe library"*

Checked against the installed `maplibre-gl@6.4.0` type declarations rather than the docs:

| Requirement | Native mechanism |
| --- | --- |
| Globe projection | `ProjectionSpecification` |
| **Smooth 2D↔globe transition** | `ProjectionDefinitionSpecification = string \| ProjectionDefinitionT \| PropertyValueSpecification<ProjectionDefinitionT>` — the projection is an **interpolatable property**, so the transition is a style animation, not a view swap |
| Atmosphere / halo | `SkySpecification`: `atmosphere-blend`, `sky-color`, `horizon-color`, `sky-horizon-blend` |
| Great-circle arcs | `line` layer over GeoJSON `LineString`; great circles are computed by us into vertices |
| Facility pins, pulse | `circle` layer + `feature-state` driven paint |
| Day/night terminator | `fill` layer over a GeoJSON polygon we recompute |
| Jurisdiction choropleth | `fill` layer, data-driven paint on an ISO code |

**deck.gl is 40+ packages and a second WebGL context for zero unmet requirements.** Not pulled
in. Recorded here so the decision is visible rather than silent, per the brief's instruction.

### DECISION 3 — the committed seed is *AI infrastructure*, not the owner's holdings. §11 is not read for it.

> §7.2: *"Seed from the holdings in §11: TSMC's Taiwan/Arizona/Japan sites, ASML Veldhoven,
> Intel's Arizona/Ohio/Ireland/Israel sites, Micron's Idaho/Japan/Singapore operations, the
> neocloud and colo footprints for CRWV/NBIS/APLD/DLR, Vertiv manufacturing."*

**This repository is public.** Each individual fact — that TSMC operates Fab 18 in Tainan — is
public knowledge and harmless. The *selection* is not: a curated file containing exactly the
facilities of exactly the companies in §11, and no others, **is a portfolio disclosure by
inference**, which is the precise thing `.gitignore` protects `portfolio.yaml` and `docs/brief.md`
from. CLAUDE.md states the test directly: *"Before adding any file that quotes the brief's §11
appendix, or any ticker list, check whether it belongs in git at all."*

The resolution needs no compromise, because the brief's own framing supplies it: this is an
**"infrastructure map, not a news globe" — "where does the physical capacity sit and which
jurisdictions constrain it."** That question is answered by the global AI-buildout footprint,
which is a public-interest dataset that stands on its own. Most of §11's names appear in it
*because they are the AI supply chain*, not because they are held.

- **`config/locations.yaml` — committed.** Curated from public AI-infrastructure knowledge.
  Built without opening §11, so the overlap is evidence about the industry rather than about the
  owner.
- **`config/locations.local.yaml` — gitignored, optional, absent by default.** Loaded and merged
  if present. This is where anything holdings-specific goes, written by the owner, exactly like
  `portfolio.yaml`.

A missing overlay is normal operation and never a warning.

## The rule that outranks everything else in this milestone

> §7.2: *"A curated, hand-maintained `locations` table — **do not auto-geocode.**"*
> *"Never plot below the threshold."*

Every pin on this map is a claim about the physical world, carrying a `source_url` and a
`verified_at` the UI must show. Three prohibitions:

- **No geocoding service, ever.** No Nominatim, no Google, no "just this once for the seed." A
  coordinate enters this system only through a hand-written config row with a citation.
- **No NER.** Gazetteer-only. §7.2 permits an optional NER pass later, off by default, behind the
  enrichment ceiling; M7 does not build it.
- **Confidence below the threshold is not plotted and not stored as if it were plotted.** A weak
  match is a weak match; `geo_confidence` is written honestly and the read path filters.

The failure mode to avoid is the one M2's clustering bug had: a *plausible* wrong answer that
looks like success. A pin in the wrong hemisphere is obvious; a pin on the right company's wrong
fab is not.

## Tasks

### Wave 1 — the data foundation (server, no UI)

**Task 1 — `config/locations.yaml` + `config/jurisdictions.yaml` + loader.**
`src/locations/load.ts`. Validation at load, not at use: a malformed `lat`, `kind`, `country`, or
a missing `source_url`/`verified_at` fails the process, matching `src/sources/load.ts`. Merges the
gitignored `locations.local.yaml` overlay when present. Exports a **content digest**
(`gazetteerVersion`) over the loaded rules, the same mechanism `src/entities/rules.ts` uses.

**Task 2 — migration `0011_geo.sql`.** Three tables, and it does *not* touch 0001's `locations` /
`item_locations`, which are already correct:
- `item_countries` — country-level matches. Deliberately **not** rows in `locations`: a
  jurisdiction is not a facility, and 0001's `kind` CHECK correctly has no `country` value.
- `item_location_extractions` — the ledger, keyed `(item_id, gazetteer_version)`, modelled on
  `item_entity_extractions` (0010) for the identical reason: zero rows in `item_locations` cannot
  distinguish "nothing matched" from "nobody looked", and that ambiguity is what let entity
  extraction stay empty for three milestones.
- `map_prefs` — §7.2's *"remember the choice server-side."* Mutable UI state, like `lane_layout`
  (0006), not a ledger.

**Task 3 — `src/locations/gazetteer.ts`.** The pure matcher: text → matches with confidence.
Alias matching with word boundaries. Confidence must be *earned* — an operator name alone is a
weaker claim than a facility's own name or a city+operator co-occurrence. Country matching is
separate and weaker still. Must be tested against **real corpus rows**, never invented fixtures
(CLAUDE.md; a fixture cannot prove a claim about real data).

**Task 4 — `src/locations/seed.ts` + `src/locations/sweep.ts`.** Seed applies config →
`locations`. Sweep is level-triggered off `gazetteerVersion`, writes `item_locations`,
`item_countries` and the ledger, and reports coverage. Mirrors `src/entities/sweep.ts`.

**Task 5 — WIRING (named owner).** Seed + sweep called from `src/bin/ingest.ts` **and**
`src/bin/scheduler.ts`. This task exists because CLAUDE.md's occurrence 8 was exactly this: the
scoring step ran in neither unattended path while the suite stayed green. Ships a test asserting
both entrypoints call the sweep.

### Wave 2 — the API (§7.1: the HTTP API is the only contract)

**Task 6 — `src/api/routes/map.ts`.** `GET /api/map/locations`, `/api/map/jurisdictions`,
`/api/map/locations/:id/items`, `/api/map/countries/:code/items`, `/api/map/arcs`.
Every click lands back in the item list — §7.2's *"the map is an index into the corpus, not a
separate destination."*

**Task 7 — `src/map/arcs.ts` + `GET/PUT /api/map/prefs`.** Arc derivation is *data*, so it is
server-side (§7.1 forbids business logic in the frontend). Arcs come from the supply relation
declared in config plus co-occurrence in the corpus; each carries a `pulseAt` — the most recent
item touching either endpoint — which is what makes an arc pulse on news.

### Wave 3 — the map itself (client, entirely code-split)

**Task 8 — basemap asset + build script.** `scripts/build-basemap.mjs` reduces Natural Earth to
`web/public/geo/countries.geojson`. Output committed; the script is reproducible and records its
source URL and licence.

**Task 9 — the lazy map chunk.** `React.lazy` + dynamic `import()` so the daily-driver bundle
never pays for WebGL. Verified by inspecting the built chunk graph, not by assertion.

**Task 10 — globe: projection transition, atmosphere, terminator.** Solar position computed
locally; no ephemeris service.

**Task 11 — arcs, pulse-on-news, layer toggles, click-through.**

**Task 12 — phone degradation + ambient mode (`?ambient=1`).** Below the ~700px breakpoint, **no
WebGL context is created at all** — §7.2 is explicit, and the existing `useIsWideViewport` hook
already draws that line for `Stream` vs `LaneBoard`.

## OPEN — the client renders geometry but never finishes loading its style

> [!warning] Status as of 2026-08-17: **the server half is done and proven; the map's data layers do not render.**

The globe draws. Projection, atmosphere, the country basemap and the 2D↔globe
toggle all work, and there is a screenshot of Europe and Africa with borders to
show for it. **What never happens is MapLibre's `load` event.** Consequently
`map.getSource()` returns `undefined`, `setPaintProperty` throws *"Style is not
done loading"*, and every layer that receives its data after load — facility
markers, supply arcs, the day/night terminator, the jurisdiction choropleth —
stays empty.

### What was ruled out, and how

| Suspect | Test | Result |
| --- | --- | --- |
| My style (sky, projection, expressions) | probe map with **no sources at all**, one background layer | also never loads — **not the style** |
| The GeoJSON data | all three `/api/map/*` fetches return 200; basemap parses to 177 features in the console | **not the data** |
| `instanceof GeoJSONSource` across module instances | replaced with a structural check that reports failures loudly | real hazard, fixed, **not the cause** |
| Blob-URL workers blocked by CSP | constructed a blob worker and round-tripped a message | works — **not CSP** |
| WebGL unavailable | `getContext('webgl2')` non-null; the globe renders | **not WebGL** |
| Dev-server-only artifact | reproduced identically under `vite build` + `vite preview` | **not dev-only** |
| maplibre-gl v6 | downgraded to v5.24.0 (same globe/sky support, verified in its own type declarations) | same failure — **not the version** |
| Stale Vite dep cache | `vite --force` | same failure |

### What WAS found along the way, and fixed

- **`optimizeDeps.exclude: ['maplibre-gl']` breaks named exports.** With it,
  the browser reports *"does not provide an export named 'AttributionControl'"*
  and the page goes blank. It was added early to silence a dep-optimizer
  warning and made everything worse while looking like progress. Removed.
- **Vite injects `import { injectQuery } from "/@vite/client"` into v6's worker
  file.** `/@vite/client` uses `document`; a Worker has none. Real, and one
  reason v6 is not the version to fight with here.
- **`worker: { format: 'es' }`** is required for v6's ESM worker and is
  irrelevant to v5, which inlines its worker.

### The thing worth saying plainly

**3,607 tests pass. `tsc` is clean. The build is clean. `web/tests/mapLazy.test.ts`
is green — the chunks split correctly, they just do not work.** This is
CLAUDE.md's characteristic defect wearing its newest costume: not "nothing calls
it", but *"everything calls it, every check agrees, and the feature is inert."*
It was found by opening the page and asking why one event had not fired, which
is the only thing that could have found it.

### Where to pick it up

`web/src/map/MapView.tsx` gates every style mutation on a `ready` flag set by
`map.on('load')`. The next thing to try is **removing that gate entirely** —
drive the layers off `styledata` with a retry, or add sources and layers inside
a `style.load` callback — and, failing that, reproduce in a plain
`vite create` app with nothing but MapLibre to establish whether this is
Watchfloor's frontend at all.

## Acceptance, and what a test cannot answer

Mechanically checkable: pins carry `verified_at`; clicking a facility returns its items; no
coordinate exists that did not come from a cited config row; the map bundle is absent from the
initial chunk graph; a phone-width viewport creates no WebGL context; zero network requests leave
the machine to render the base map.

**Not checkable by any test** — and therefore the owner's call, exactly as §7's terminal-vs-feed
question still is:

- Does the jurisdiction layer *tell you something you did not already know from reading the lanes*?
  If it does not, the layer has failed regardless of whether it renders.
- Is the globe with live arcs something you would leave running on a spare monitor?
